# WOW W7-CUST-BYZ-02 — отдельный изменённый кастодиан по Roha/noq

**Цель:** перейти от локальных контрпримеров [W7-CUST-BYZ-01](https://app.notion.com/p/40132a84beec81d98477c8b58088d1e5) к **отдельному процессу оператора**, имеющему действительный собственный Ed25519-ключ и реальный Roha/noq QUIC/TLS EndpointId. Проверить, что даже валидная подпись кастодиана и настоящий защищённый транспорт не дают ему права завершать доставку.

**Код:** `src/bin/w7_rogue_custodian.rs` — намеренно злонамеренный тестовый сервер, доступный только с включённой возможностью `iroh-transport`. Его нельзя развёртывать как почтовую службу. `tests/rogue_process_quic_w7.rs` запускает бинарник как **другой процесс ОС**, самостоятельно устанавливает TLS/QUIC к нему по `127.0.0.1` и проводит проверки. Отдельная работа в разных процессах на одном Linux-исполнителе — **не два физических компьютера**.

## Сетевой контур и полномочия

- Сервер публикует только временные EndpointId и `127.0.0.1:порт`; внешние реле, интернет, незнакомые сети и доступ к Vault не используются.
- Соединения Roha/noq/QUIC/TLS проходят настоящую проверку EndpointId. Сервер отдельно закрепляет три идентификатора: отправитель A (STORE), аудитор (AUDIT), получатель B (FETCH), полученные при запуске в лаборатории. Любой четвёртый узел отклоняется.
- Приватный `W3 v3` создаёт отправитель один раз с **настоящими HPKE и Ed25519**; каждый ответ сверяется по эталонному BLAKE3, вычисленному на стороне A. Сервер **не получает** HPKE-секрет B.
- Для запросов AUDIT и FETCH используются **разные тестовые ограниченные возможности**, проверяемые совместно с подлинным сетевым EndpointId. Публичный 16-байтный W3 `route_token` не является разрешением на чтение.
- Используется **отдельный испытательный протокол** `akula-wow/w7-hostile-custodian-local-only/1`. Он нарочно не имитирует полную производственную авторизацию `W6 RelayGrant` или шифрованный обратный путь W4: здесь исследуется именно невозможность доверять чужой программе только по подписи и защищённому транспорту. В производственный WOW этот протокол не добавляется.

## Сценарии

| Режим чужого процесса | Что он делает | Ожидаемый результат у честных A и B |
| --- | --- | --- |
| `fake` | Подписывает CustodianStored **вообще не записав** W3 | Валидное заявление C; независимый AUDIT пуст; W4 отсутствует |
| `delete` | Сохраняет W3 в SQLite, подписывает, затем удаляет SQL-строку в обход API | Подпись C остаётся, последующий AUDIT пуст, письмо у A остаётся в очереди |
| `censor` | Правильно хранит W3 и отвечает аудитору, но умышленно не отдаёт B | Аудит успешен, B не получил, конечной W4 нет |
| `corrupt` | Возвращает повреждённый ciphertext | Независимый digest не совпадает, HPKE/подпись отвергают пакет |
| `honest` | Записывает и честно выдаёт неизменённый W3 | Только B с секретом HPKE и ключом W4 заканчивает доставку |
| `drop-ack` | Сохраняет правильный W3, но не возвращает квитанцию STORE | У A неопределённый результат, у аудита/B данные есть; отсутствие ACK не доказывает отсутствие записи |

Общие отрицательные проверки: другой TLS EndpointId с украденным правом; действительный EndpointId с неверным секретом чтения; аудитор пытается использовать право B; поддельная W4, реально подписанная собственным ключом кастодиана, но выдаваемая за подпись B — отклонена. Ни один чужой ответ не переводит исходящий `Journal` в `Delivery::Recipient`.

## Граница результата

- **Изолированность:** отдельный ОС-процесс и отдельная SQLite у сервера, но общий Linux GitHub runner, не отдельная физическая машина.
- **Настоящая сеть:** QUIC/TLS по localhost и закреплённый EndpointId, не имитация функций отправки.
- **Существующий W6 обработчик не тестируется здесь на авторизацию приёма**, поскольку вредоносный форк использует собственную операцию STORE; в W6 основные проверки RelayGrant остаются отдельными регрессиями.
- **Нет настоящего злоумышленника в интернете:** сервер намеренно сконструирован нами, использует тестовые известные ключи и фиксированные возможности; гарантируется только поведение исполняемых проверок.
- **Нет скрытой W4:** финальная W4 выдаётся локально B после приёма, но пока нельзя пересылать её через произвольного общедоступного кастодиана в открытом виде.
- **Нет глобального доказательства K3:** два независимых злонамеренных C могут сделать сколько угодно физически копий, запретить нельзя. [WOW #67](https://github.com/calex794/wow/issues/67) остаётся открытой задачей логического переносимого права.
- **Нет наказания по тайм-ауту:** `AUDIT=Unavailable` трактуется как отсутствие наблюдения доступности, а не однозначное мошенничество.

```bash
cargo test --features iroh-transport --test rogue_process_quic_w7 -- --nocapture
cargo clippy --features iroh-transport --all-targets -- -D warnings
```

Интеграционный опыт включён в уже имеющееся задание `w6_iroh_quic` существующего `.github/workflows/rust.yml`; отдельного тяжёлого задания GitHub Actions не создаём. Общие W4, W5, W6 и ENOSPC-проверки должны остаться зелёными.

**После приёмки:** разработать приватный сетевой ответ W4, формальный сетевой `FetchAndVerify` с разрешениями и сроками, учёт неоднозначного `CustodyOffer` между независимыми SQLite и опыт на двух физических машинах [WOW #69](https://github.com/calex794/wow/issues/69).
