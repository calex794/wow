# LABO EXP-018 → WOW: signed W4 and independent gateway custody gate

Date: 2026-10-23. Experimental bridge between [LABO EXP-018](https://github.com/calex794/labo/pull/24) and the existing WOW implementation. **NOT** a mobile, WAN or SFHH/InVS packet replay.

## What is integrated

- The original immutable encrypted W3 v3 is generated by the existing Blue-backed WOW adapter and stored by the source in its own SQLite (WAL + FULL).
- Under **one local K=4 budget**, the source reserves two distinct gateway slots before issuing W8 Ed25519-signed custody offers. Two peers accept the *exact same encrypted packet* into two independent SQLite databases; their signed acknowledgments are checked against the trust registry. A peer ACK means custody **only**, not RecipientStored/SourceConfirmed.
- In the disk-loss case, gateway A's SQLite file is deleted after its acknowledged commit. The packet is retrieved from gateway B's *persisted* SQLite, then verified and committed to the recipient's separate SQLite. The recipient's W4 is Ed25519-signed **in the same recipient transaction** and is available after restart.
- The return W4 is carried in an HPKE opaque envelope with an invitation-specific tag; the source checks return token, invitation expiry, recipient Ed25519 identity and **BLAKE3 hash of exact W3** before atomically marking Recipient and stopping outstanding K4 route slots. Forged custodian-signed W4 is rejected.
- A duplicate signed W4 after sender restart does not create a second delivery or resurrect credits. A genuine receipt may arrive after **forward-message TTL**, provided the distinct return invitation is still valid.
- With both gateway disks absent and no recipient commit, the source remains *not RecipientConfirmed* even after peer custody ACKs. Its original copy is still present until TTL; we do not claim permanent undeliverability.

## Acceptance

Run:

```sh
cargo test --test labo_exp018_signed_w4_gate
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
```

Three new composition tests cover: (1) gateway A disk reset, B rescue, signed W4 and restart; (2) no false recipient confirmation from peer custody ACK with both gateways gone; (3) distinction between W3 TTL and signed W4 return-invitation expiry.

These tests use the established WOW implementations, not parallel reimplementations of crypto or storage. Do not merge on the strength of these tests alone if regression CI fails.

## Strict evidence boundary

- **Verified:** real Ed25519 signatures, real HPKE encryption/decryption, real SQLite commits/reopens on one CI runner, copy-slot fencing, deterministic fault injection in Rust tests.
- **Not verified:** physical isolation of gateways, radio/WAN transport, relay malicious network behavior, Bluetooth service limits, SFHH/InVS end-to-end replays, Android/iOS background behavior, global Byzantine K=4 enforcement, real energy/latency, recipient application of contents to Sync Core.
- The LABO Python metrics still use **synthetic** SourceConfirmed markers. There is no direct translation from aggregate `outage-comparison.json` to per-letter W4 objects yet. To bridge actual contact traces, LABO must publish a validated *per-message event trace* (same seeded message ID, sender/recipient mapping, gateway commits, first successful mailbox upload, recipient commit time and reverse transit); this test does **not** pretend that already exists.
- For live Akula, separate key provisioning, endpoint authentication, privacy audit, permissioning, actual network transport and physical two-computer acceptance are still required.
