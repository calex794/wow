# WOW W7-CUST-BYZ-01 — изменённый кастодиан, реальные подписи и недоверенное хранение

**Назначение:** не запрещать форки, а проверять устойчивость честных клиентов WOW к произвольно изменённой программе добровольного кастодиана. [Сводная теория WOW-CUSTODIAN-03](https://app.notion.com/p/40132a84beec8196bafde11cf414ef05).

**Среда:** реальные W3 v3 Blue (HPKE + COSE/Ed25519), реальные подписи Ed25519 `CustodianStored` и конечной W4, настоящий SQLite `Mailbox` / `Journal`. Все испытания локальные, без физических разных машин и без утверждения о честности сторонних узлов. Вредоносный код работает только с синтетическими письмами. Проверки выполняются существующим `rust.yml`; новых тяжёлых сценариев Actions нет.

## Главный закон

**Наша программа и её проверенный выпуск не могут принудить удалённый кастодиан исполнять неизменённый код.** Любой оператор может подписать `CustodianStored` своим действительным ключом вообще без записи. Криптографически верная подпись означает лишь «этот узел заявил о хранении». Отдельное наблюдение правильного ciphertext в момент t тоже не доказывает, что узел хранит его независимо и будет отдавать адресату завтра.

## Новое правило проверки наличия

Добавлен `src/custody_audit_w7.rs` — малый проверяющий для **доверенно известного точного ciphertext**. Он:
- закрепляет длину и BLAKE3 исходных W3 байтов (эталон выдаёт отправитель/получатель, но **не кастодиан**);
- после отдельной аутентификации/разрешения Fetch сверяет полученный W3 и фиксирует только **наблюдение доступности на заданный проверяющим момент**;
- возвращает `Unavailable` при отсутствии ответа и `WrongLength` / `WrongCiphertext` при повреждении;
- **не** генерирует и не приводит к финальной W4; W4 выдаёт только B после проверки W3 и долговечной записи;
- не доказывает, что байты были прочитаны именно с локального физического диска, а не скачаны по запросу у сообщника. Право на Fetch — отдельное ограниченное полномочие, не маршрутный токен.

Это **локальное средство независимого наблюдения**, не законченная сетевая служба аудита. Тип наблюдения нельзя превращать в гарантию непрерывного хранения. Нет автоматической репутации/глобального наказания по одному сетевому тайм-ауту.

## Пятнадцать атак/контрольных сценариев

| № | Сценарий | Что наблюдаем | Ограничение / нужное развитие |
| --- | --- | --- | --- |
| 1 | `FakeStored`: собственный действительный Ed25519 без сохранения | Подпись верна, чтение отсутствует, W4 не возникает | Ложная подпись сама неотличима от обещания |
| 2 | `StoreThenDelete`: сохранить в SQLite, подписать и удалить запись напрямую | После перезапуска чтение пусто, A остаётся в очереди | Узел может удалить сразу после аудита |
| 3 | `SelectiveCensor`: отдать аудитору, но скрыть от B | Аудит «было доступно», W4 нет | Аудит не доказывает общедоступность B |
| 4 | `TamperW3`: заменить байт/усечь письмо | Несовпадение BLAKE3, HPKE отвергает | C всё равно может полностью блокировать |
| 5 | `ForgeW4`: C подписывает фиктивную конечную W4 | Не проходит независимый доверенный ключ B | W4 всё ещё требует приватного обратного маршрута |
| 6 | `ReplayClaim`: старый срок, чужой slot, подмена подписи | Подтверждение C отвергнуто | Нет внешней гарантии отсутствия rollback всего журнала |
| 7 | `CopyAndSpread`: C делает 10 байтовых копий | Честный K3 не может ограничить физические копии | Глобальная физическая K3 невозможна без доверия |
| 8 | `SybilSharedDisk`: два ключа и один файл SQLite | Оба доказательства/аудита проходят; общая потеря рушит оба | Независимость дисков не доказана |
| 9 | `ForkLease`: два подписанта предъявляют один slot | Видны два совместимых по формату утверждения, A без W4 | Требует отдельного протокола передачи и обнаружения вилок, [WOW #67](https://github.com/calex794/wow/issues/67) |
| 10 | `RollbackEpoch`: старый подписант после обновления/отзыва ключа | Проверка по текущему реестру отвергает | Полный откат самого реестра без внешней опоры — пробел |
| 11 | `OfflineHonest`: честный узел не отвечает | `Unavailable`, не доказательство мошенничества | Политика повтора/тайм-аута |
| 12 | `FakeOfficial`: самореклама «официальная сборка» | Самореклама не входит в криптографическую проверку | Подпись релиза ≠ аппаратная аттестация |
| 13 | `CorruptStorage`: модифицировать строку SQLite | `Mailbox::get_page` возвращает `CorruptStorage` | Недоступность не должна стать W4 |
| 14 | `AuditNotReceipt`: успешный аудит | Сам по себе не переводит `Journal` в `Delivery::Recipient` | Не принимать аудит за конечную квитанцию |
| 15 | **Положительный контроль:** B сам проверил W3 и записал в SQLite | Подлинная W4 останавливает повторы, повтор приёма идемпотентен | Это надёжный локальный приём, не доказательство сквозной физической сети |

**Главный исследовательский результат должен включать и ограничения:** сценарии 7–9 не «устраняются» 15 тестами. В частности подлинные `CustodianStored` от двух разных PeerID и успешное чтение из одного файла **не** доказывают наличие двух независимых копий (аналог [FAIR-LAB-06](https://app.notion.com/p/3fd32a84beec81ef84f2d7b61c1470a4)).

## Приёмка

```bash
cargo test --test byzantine_custodian_w7
cargo clippy --all-targets -- -D warnings
```

В штатном PR также должны завершиться существующие независимые W6 QUIC и W4/W5 ENOSPC задания. **Не добавлять** пятый тяжёлый сценарий CI для этих 15 тестов.

## Что не входит

Это не удалённый кастодиан с произвольным чужим исполняемым файлом, не полноценный Proof of Retrievability, не подписанная аппаратная аттестация, не физические два сервера, не закрытая W4 поверх релея и не устойчивость к сговору при подмене конечных ключей. Публичный GitHub CI доказывает только работу локальных регрессионных тестов на коде main/PR, **не** исправление мировых сетевых ограничений.
